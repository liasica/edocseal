# 签约企业与证书

合同签署时，edocseal 在 PDF 上加两处签名：企业签名（签约企业的证书与签章）和个人签名（签约人的证书与手写签名）。本文说明两类证书的来源、签发与复用规则，以及签约企业和根证书的管理方式。

## 证书生成方式

| 取值 | 含义 |
| --- | --- |
| `SELF` | 自签：由本服务的根证书签发 |
| `SNCA` | 陕西CA：向陕西CA 申请 |
| `SNCA_V2` | 陕西CA 新接口：尚未对接，收到该值时签约返回「不支持的证书生成方式」 |

生成方式在管理后台「系统设置 -> 证书生成方式」中选择，aurservd 签约时通过 `Sign` 请求的 `certificate_issuer` 原样传入。请求未携带时按配置项 `selfSign` 决定：`true` 为 `SELF`，否则为 `SNCA`。

## 个人证书

- 按身份证号查询未过期的证书记录（`certification` 表），有则直接复用，不区分签发方式；记录有效期为签发后 24 小时减 10 分钟。
- 没有可用证书时按生成方式签发，证书与私钥保存在证书目录的 `<身份证号>_cert.pem`、`<身份证号>_key.pem`，记录中的 `issuer` 列记下签发方式。
- 自签个人证书：主题 `CN=<身份证号>, O=<姓名>, OU=<身份证号>`，有效期 1 年。
- 陕西CA 个人证书：本地生成 RSA 私钥与 P10，向陕西CA 申请。

## 签约企业

签约企业在管理后台「签约企业」页面管理，操作经 aurservd 调用本服务的 `EnterpriseService`，立即生效，无需重启：

- 新增或修改：统一社会信用代码（18 位）、企业名称、省份、城市、代办人姓名／手机号／身份证号（向陕西CA 申请企业证书时必填）、签章图片（PNG）。修改时不上传签章则保留原签章。
- 设为签约企业：合同的企业签名使用当前签约企业；第一个新增的企业自动成为签约企业。
- 删除：当前签约企业不能删除；删除时一并删除其证书记录与签章文件。
- 作废证书：删除该企业的全部企业证书记录，下次签约时重新签发。

存储与缓存：

- 企业资料存 `enterprise` 表，签章存签章目录下的 `<统一社会信用代码>.png`。
- 服务启动时把全部企业和企业证书记录加载到内存，签约只读内存；后台操作和证书签发串行执行，先写数据库再刷新内存。
- 容器内可用 `./edocseal enterprise list` 查看企业与企业证书；新增、修改、切换与作废只在管理后台操作。

## 企业证书

- 按「统一社会信用代码 + 生成方式」各保存一张（`enterprise_certification` 表），证书文件在证书目录的 `enterprise/` 子目录。
- 签约时没有该生成方式的证书，或剩余有效期不足 7 天，就自动签发；签发失败而旧证书尚未过期时继续使用旧证书。
- 企业名称、省份或城市修改后，该企业的证书自动作废。
- 自签企业证书：由根证书签发，主题 `CN=<企业名称>, O=<企业名称>, OU=<统一社会信用代码>, ST=<省份>, L=<城市>, C=CN`，非 CA 证书，用途为数字签名与不可否认，有效期 10 年。
- 陕西CA 企业证书：配置了 `enterprise.url` 时从该地址按 `?code=<统一社会信用代码>` 拉取证书与私钥；未配置时用企业代办人信息直接向陕西CA 申请。

## 根证书

- 主题：`CN=陕西极光换电科技有限责任公司 Root CA, O=陕西极光换电科技有限责任公司, OU=91610103MACUXL1W1A, ST=陕西省, L=西安市, C=CN`，有效期 99 年，定义在 `internal/model/ca.go`。
- 文件路径由配置项 `rootCertificate.certificate` 与 `rootCertificate.privateKey` 指定，每次签发时读取文件，替换文件后无需重启。
- 管理后台「签约企业」页面可查看根证书信息并重新生成。重新生成在服务器上完成，私钥不经过浏览器与 aurservd；原文件加 `.<时间>.bak` 后缀备份，全部自签的企业证书与个人证书记录随之作废，下次签约按新根证书签发。
- 也可在容器内执行 `./edocseal certificate root -p <目录>` 生成到指定目录。

## 配置项

```yaml
selfSign: false            # 签约请求未携带生成方式时是否自签

dir:
  certificate: ./certificates   # 个人与企业证书目录
  seal: ./config                # 企业签章目录，为空时使用配置文件所在目录

rootCertificate:
  certificate: ./config/rootCA.crt
  privateKey: ./config/rootPrivateKey.pem

enterprise:
  url: http://<正式机>:5015/enterprise/cert/<令牌>   # 测试机配置：陕西CA 企业证书从正式机拉取
  token: <令牌>                                      # 正式机配置：对外提供企业证书接口的令牌，为空时不提供
```

## 接口

- gRPC `ContractService.Sign`：签署合同，`certificate_issuer` 为证书生成方式。
- gRPC `EnterpriseService`：`List`、`Save`、`Delete`、`SetDefault`、`RevokeCertificates`、`RootCertificate`、`RegenerateRootCertificate`，定义见 `pb/enterprise.proto`，出错时返回 `FailedPrecondition` 与错误原因。
- HTTP `GET /enterprise/cert/{token}?code=<统一社会信用代码>`：返回该企业的陕西CA 证书与私钥（PEM），`code` 为空时返回当前签约企业的；本机没有可用证书时先向陕西CA 申请。

## 环境与上线

- 只有正式机向陕西CA 申请企业证书；测试机配置 `enterprise.url` 从正式机拉取，避免重复申请真实证书。两台的令牌需一致。
- 新环境首次上线后，签约前必须在管理后台至少新增一个签约企业并上传签章，否则签约返回「未设置签约企业」。
